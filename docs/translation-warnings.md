# 翻译警告与单次生成（alpha.21）

此处描述 alpha.21 的行为。下方两轮日志是版本递增前的实现阶段验证（当时为 versionCode 20），不能作为 alpha.21 APK 身份证明；alpha.21 独立的完整重跑、远端 CI 与签名下载要求见[发布验证记录](reports/alpha21.md)。历史 alpha.20 发布与验证记录保持不变。

## 显示与缓存

- 保护片段校验不一致时，不丢弃非空译文，尽力恢复**该句自己**的已知占位符，在末尾追加普通文本：
  `译文正文。 *****（protected_token_mismatch）`
- 不猜补漏掉的数字、公式、引用，不把其他句子的标记还原成当前句的内容；未知/被改写的标记保留可见。
- **不限于保护标记或语言校验**：任何失败已有可归属的非空译文，就保留正文并标注对应错误码，例如 `*****（truncated_stream_length）`、`*****（http_500）`、`*****（host_timeout）`、`*****（invalid_translation_json）`。错误码转小写、规范化为有界英文代码；多个诊断在同一尾缀内以英文逗号分隔，不重复。
- PDF 与 TXT 的尾缀与译文处于同一个纯文本节点，不解析 Markdown/HTML，不新增颜色、下划线、字体、粗体或错误提示样式；浅/深色均继承相邻译文的黑灰度。
- Web 还有通用失败兜底：如果 Native 未能提交（例如缓存写入失败），保留当时的草稿/已收到译文并用普通 `done` 样式显示尾缀，但内部仍保留失败状态供用户显式重试，不伪造持久化成功，也不把真正的取消当作错误。
- 带标注的正文先持久化再提交界面，重新打开时按普通缓存恢复，不因同一警告再次生成。有效的旧缓存和现有内容键/配置指纹不变，不清空缓存、不迁移数据库。历史未标注的明显原文复制仍会视为缓存未命中，新生成也只尝试一次。

## 生成次数与失败

- 移除队列的批次失败→逐句修复→纯文本修复三轮自动生成；每个缺失批次/上下文分片只请求一次。
- 流中断、截断、超时、超限或 JSON 外壳错误时，提取明确属于本句的完整行或末行已收到的正文，追加实际错误码并持久化；长句后续分片失败也保留已完成的前文。非流式 API 已返回正文但结束原因不正常时，同样保留正文，不再次请求。
- 不猜句子归属：重复 ID 不择一覆盖，未知 ID 不分配给其他句子，JSON 结构壳与思考内容不当作译文。无法安全取得正文（空输出、无对应行、歧义 ID 等）时，只显示该错误提示；已可归属的相邻行不丢失。
- 保留 provider 内 GPU→CPU 兼容回退及 `Restart` 清除 GPU 草稿行为，并将回退收紧为明确的 Vulkan 不可用/未构建/预热失败/非有限 logits/设备丢失、GPU 上下文分配失败及 `vk::` 后端异常。普通截断、输出超限、UTF-8/指标错误、坏 GGUF 与未知异常不会再被当作兼容问题触发第二轮生成；CPU 回退后仍失败则直接结束。
- API 翻译客户端关闭连接故障自动重发，并阻止 OkHttp 对 `503 + Retry-After: 0` 的隐式 POST 重放；408/503/断连接均直接返回当前请求的失败。
- 用户主动点击失败句/重试任务仍可发起新请求。取消、抢占、等待底层推理排空、后台断点恢复与只阅读策略不变；恢复只补未完成内容。
- 长句仍按既有上下文预算分片，复用已完成分片；最终将各分片警告去重并集中放到整句末尾，不重复整句推理。

## 验证范围

Core 单元测试验证普通失败单次调用、宽容恢复、缓存复用、分片与取消；原有 Engine 假运行时测试覆盖兼容回退。共享 Web 渲染与缓存恢复测试检查纯文本和正常状态。`scripts/test_reader.mjs`、`scripts/test_text_reader.mjs` 使用实际生成的资源，在浅/深色下检查警告与相邻正常译文样式完全一致、无子节点、无下划线，并验证重新打开不请求推理。

浏览器中的 Native、存储与译文为模拟输入，不是 Android 真机、真实模型或 Room 仪器化执行证据。设置 `PARAREAD_REPORT_DIR` 可将浏览器报告输出至独立目录，避免覆盖历史发布证明。
