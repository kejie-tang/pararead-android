# 原文直译与运行兼容性

此处描述 **alpha.22** 的原文直译策略，见[本版验证记录](reports/alpha22.md)。alpha.21 及更早版本的 APK、tag、附件与历史验证记录均不替换。下方旧实现日志只记录当时的行为，不代表本轮策略。

## 不干预译文质量

- 原文直接进入翻译请求：数字、公式、引用、URL、代码和原文中的字面量 `__PR0__` 都不替换、不还原，不注入占位符，也不拒绝所谓保留字。
- JSON 中的 `text` 与原句一致；文本模式同样直接使用原文。长句仅按上下文预算连续分片，边界不拆 Unicode 代理对，重新拼接严格等于原文；不保证公式或 URL 整段不可分。
- prompt 只保留翻译任务、目标语言及必要的 JSON/ID 或纯文本输出协议。删除逐字复制标记、保护数字/引用/代码、否定/转折、禁止总结等额外质量训令。默认空术语表不写进 prompt；用户显式配置的非空术语表仍可使用。
- 不检查中文比例、英文/原文复制、数字或引用是否遗漏，不生成 `protected_token_mismatch` 或 `translation_language_or_source_copy`；译得不准也不因此重试、拒收或加质量标注。
- 只检查程序运行协议：空正文、大小限制、JSON 外壳、唯一且已知的句子 ID、字符串类型、推理内容隔离。不能把别句、推理过程或 JSON 结构当成译文。

## 运行失败与显示

- 流截断、HTTP/超时、运行异常、格式错误已有可安全归属的正文时保留正文，并追加实际运行错误码，例如 `译文（http_500）`。用户示例中的星号只是占位符，界面不添加星号。
- PDF/TXT 均使用普通纯文本，与附近译文同色同字体；不解析 Markdown/HTML，不新增红色、下划线、加粗或强调。
- 无安全正文时才显示失败提示；普通失败不自动再次生成、不隐式重发 HTTP。仅明确的 GPU/后端兼容性失败允许一次 CPU 回退；`Restart` 清除旧 GPU 草稿。
- 保存成功后才提交已保存状态；保存失败保留可见草稿但不伪造持久化成功。用户显式重试、取消、抢占、单推理所有者、等待排空、只阅读及安全退出门禁保持不变。

## 缓存兼容

- 新请求使用 `prompt=7 / validator=7`，模型模板和 native grammar 身份不变。新键优先，只允许同模型、模型哈希、语言与术语表配置的已知 `6/6` 旧键回退；不清库、不迁移、不跨配置搜索。
- 整句、分片和只恢复缓存入口共享兼容规则。旧缓存命中不推理、不写回/晋升，提交时携带实际命中的旧键；cache-only miss 也不发起推理。
- 读取旧尾缀时去掉质量标注及占位星号，保留正文和真实运行错误码。正文中真实的星号不做全局删除。
- 无法还原的旧 `__PR数字__` 输出不猜补，旧格式缓存视为不可用；此限制只针对旧键，新原文中的字面量标记正常通过。
- 已有有效缓存仍直接复用，因此不会自动变成新 prompt 的译文。旧整篇任务游标仍要求精确配置指纹，不冒充新策略任务或暗中改配置重跑。
